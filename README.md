# Pharma Transfer Pricing Data Pipeline

A Python data pipeline for a pharmaceutical group's Transfer Pricing (TP)
analysis: it cleans an SAP-style ERP export, classifies transactions,
benchmarks each entity against arm's-length studies (region-aware, full
quartile statistics), and produces a clean dataset ready for Power BI.

Structured like a real project - grouped by responsibility (I/O, cleaning,
domain model, benchmarking, ...) rather than by tutorial topic. See
[`docs/CONCEPTS.md`](docs/CONCEPTS.md) if you want to see where a specific
Python fundamental (generators, OOP, error handling, ...) is used.

## Business context

A classic pharma "Principal structure" across 3 regions, 6 legal entities:

| CompanyCode | Legal Entity | Region | Role | Benchmarked on |
|---|---|---|---|---|
| US02 | PharmaCorp Global Principal Inc. | Americas | Principal (owns the IP) | not benchmarked - residual profit |
| US05 | PharmaCorp USA Distribution Inc. | Americas | Distributor | Operating Margin |
| DE01 | PharmaCorp Deutschland GmbH | EMEA | Distributor | Operating Margin |
| FR03 | PharmaCorp France SAS | EMEA | Distributor | Operating Margin |
| SG01 | PharmaCorp Singapore Pte Ltd | APAC | Distributor | Operating Margin |
| CH04 | PharmaCorp Manufacturing AG | EMEA | Contract Manufacturer | **Full Cost Mark-up** |

All entities except the Principal also pay a trademark/know-how royalty,
benchmarked against a global Royalty Rate study.

```
6 Excel inputs ──▶ main.py ──▶ output/powerbi_transfer_pricing_dataset.csv
                            └─▶ output/unmapped_transactions.csv (data-quality log)
```

## The data model

**`raw_erp_export.xlsx`** — one row per journal posting. `CompanyCode` is
always the entity that **raises the invoice**; `PartnerCompanyCode` is the
intercompany counterparty, blank if the counterparty is a third party. GL
accounts: **4000** Distribution, **4100** Contract Manufacturing, **4200**
IP/Licensing, **4900** intentionally unmapped (drives the error-handling
path).

**`entity_financials.xlsx`** — a genuine, simple P&L per entity: one
`Revenue` line plus `COGS`/`SGA`/`RD`/`OtherOpex`. No group-level revenue
split lives here - that split is *derived* from the journal, so there's a
single source of truth and the reconciliation check is meaningful rather
than circular.

**No `FunctionalRole` column anywhere** — derived at runtime
(`roles.py`) from which GL account an entity invoices most often.

**`benchmark_studies.xlsx`** is region-aware and carries full quartile
statistics (`Min`, `LowerQuartile`, `Median`, `UpperQuartile`, `Max`,
`NumberOfComparables`) like a real benchmark study would, instead of a
single low/high pair. The arm's-length test uses the interquartile range
(OECD-standard practice); Min/Max are used to flag genuine outliers vs. a
merely "worth a second look" grey zone.

**Contract Manufacturing is benchmarked on Full Cost Mark-up**, not
Operating Margin — a cost-based, limited-risk manufacturer doesn't control
its own sales price, so it's tested on what it earns on top of its own
costs instead of on revenue.

**`fx_rates.xlsx`** provides a group reporting currency (EUR) so the final
dataset includes `RevenueEUR` / `OperatingProfitEUR` alongside each
entity's local-currency figures.

This run's sample data is deliberately calibrated so **most entities land
within their benchmark range, but not all**:
- **US05** (new Americas distributor) comes in *below* the benchmark Min —
  a genuine outlier (ramp-up losses at a newly launched entity).
- **FR03**'s royalty rate lands *just above* the Upper Quartile but inside
  Max — a grey zone worth a second look, not yet a hard outlier.
- Everyone else sits comfortably inside their interquartile range.

## How the pipeline works (`src/tp_pipeline/pipeline.py`)

1. **Read** all 6 source files.
2. **Flag** each journal row Intercompany vs. Third Party.
3. **Clean** every row, attach its `TransactionGroup`, route unmapped GL
   accounts to a data-quality log instead of crashing.
4. **Derive** each entity's functional role from its invoicing pattern.
5. **Calculate & classify**: Operating Margin (Distributors), Full Cost
   Mark-up (Contract Manufacturer), Royalty Rate (every royalty payer) -
   each checked against its region-specific (or global) benchmark using
   the 3-tier Min/Quartile/Max classification.
6. **Reconcile** the journal total against the financials total, with any
   difference explained.
7. **Export** one row per entity to `output/powerbi_transfer_pricing_dataset.csv`,
   plus a data-quality log of unmapped rows.

## Setup & run

```bash
pip install -r requirements.txt

# (optional) regenerate the sample Excel files
python3 data/generate_sample_data.py

# run a single module to study one concept in isolation
python3 -m tp_pipeline.roles          # from inside src/, or:
PYTHONPATH=src python3 src/tp_pipeline/benchmarking.py

# run the full pipeline
python3 main.py
```

## Tests

```bash
pip install -r requirements-dev.txt
pytest tests/
```

## Ideas to extend this for your portfolio

- Swap the sample Excel files for a real (anonymized) SAP export.
- Add a second Contract Manufacturing entity in a different region to
  fully exercise the region-aware benchmark lookup for that group too.
- Add more periods (quarterly instead of annual) for time-series analysis.
- Wire the CSV output into a scheduled Power BI refresh or a small database
  instead of a flat file.
